# M0 · Base — Plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.


> **Desvios na execução (2026-11-20):** as migrações rodam no início do container (`scripts/iniciar.sh`), não como pré-deploy do Coolify, que executa no container antigo; o SSH usa `PermitRootLogin prohibit-password` (só a chave do Coolify em `/root`), porque o Coolify gerencia o servidor como root; a imagem tem `HEALTHCHECK` próprio (`dist/checar-saude.js`). O roteiro atualizado está em `docs/operacao/servidor.md`.

**Goal:** Deixar no ar, numa VPS em São Paulo, a base da plataforma: aplicação Next.js com login da equipe e painel protegido por papel, banco Postgres com o modelo de dados núcleo do MVP, integração contínua, deploy pelo Coolify, backups diários fora da VPS com uma restauração verificada e monitoramento.

**Architecture:** Um monólito Next.js (App Router) que fala com um Postgres via Drizzle ORM. Migrações SQL versionadas em `drizzle/` rodam como comando de pré-deploy no Coolify. A autenticação é feita na própria aplicação com Better Auth (e-mail e senha, cadastro público desligado). Pessoas e papéis ficam nas tabelas do domínio, ligadas ao usuário do Better Auth. O registro de consentimento é protegido por gatilhos do Postgres que impedem alteração e remoção.

**Tech Stack:** Node.js 26 (LTS ativo), pnpm, Next.js 16, React, TypeScript estrito, Tailwind CSS 4, Drizzle ORM + drizzle-kit, node-postgres (`pg`), Better Auth + `@better-auth/drizzle-adapter`, Zod, Vitest, Biome, Docker, GitHub Actions, Coolify, PostgreSQL 17.

**Spec:** `docs/superpowers/specs/2026-11-20-mvp-marcos-design.md` (seção 7, M0). Contexto do produto: `contexto-arquitetura-danca.md` no projeto do claude.ai.

## Global Constraints

- Interface, mensagens de erro, comentários no código e documentação em português do Brasil. Nomes do domínio em português (`pessoas`, `turmas`, `registrosConsentimento`).
- Node.js 26 (`.nvmrc` = `26`, `engines.node` = `>=26`). Next.js 16.x. TypeScript com `strict: true`.
- Nenhum segredo commitado. `.env*` no `.gitignore`, exceto `.env.example` sem valores reais.
- Ritmos, módulos e tipos de consentimento são linhas no banco, nunca enums ou constantes no código. Papéis de pessoa são um enum fixo: `administracao`, `atendente`, `professor`, `aluno`, `responsavel`.
- O registro de consentimento só recebe novas linhas. UPDATE, DELETE e TRUNCATE são bloqueados no banco. Pessoas com registros de consentimento não podem ser removidas.
- Toda data e hora em `timestamptz`. Data de nascimento em `date`. Horário de turma em `time`.
- Toda tela é pensada primeiro para o celular e verificada em 375 px, 768 px e 1280 px de largura. Use a skill design-craft em toda tela.
- Toda mudança de código começa por um teste que falha (superpowers:test-driven-development). Tarefas de infraestrutura têm um passo de verificação com o comando e a saída esperada.
- Trabalho em branch com pull request. Mensagens de commit em português, no formato `tipo: descrição` (`feat`, `fix`, `chore`, `docs`, `test`).

## Review Focus

1. **Força bruta no login:** muitas tentativas de senha a partir do mesmo IP devem ser barradas. Teste na Tarefa 8: a 6ª tentativa errada em 60 s responde 429.
2. **E-mail com maiúsculas ou espaços:** `" Ana@Estudio.com "` e `"ana@estudio.com"` são a mesma pessoa. O e-mail é normalizado (minúsculas, sem espaços) e único sem diferenciar maiúsculas. Teste na Tarefa 4.
3. **Verificação de saúde vazando detalhes:** com o banco fora do ar, `/api/saude` responde 503 sem mensagem de erro, pilha ou endereço de conexão. Teste na Tarefa 3.
4. **Apagar consentimento por SQL direto:** UPDATE, DELETE e TRUNCATE em `registros_consentimento` e em `textos_consentimento` falham mesmo para o dono das tabelas. Teste na Tarefa 6.
5. **Deploy repetido:** rodar as migrações duas vezes seguidas (o Coolify roda a cada deploy) não falha nem altera nada na segunda vez. Teste na Tarefa 2.
